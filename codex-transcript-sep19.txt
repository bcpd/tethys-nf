▌why kofam_cpus = 1?

> It’s a tuning choice to maximize parallelism, not a requirement.

  - Per‑task threads: KOFAM_SCAN passes --cpu = task.cpus to exec_annotation. Setting kofam_cpus=1 means each task uses
  1 thread.
  - Concurrency vs. throughput: With many genomes, running more 1‑thread tasks in parallel typically drains the queue
  faster than a few big multi‑threaded tasks. On an 8‑core box, 8×1‑thread tasks often outperform 1×8‑thread due to better
  scheduling and sub‑linear scaling in exec_annotation/HMMER.
  - Resource balance: 1–2 threads per task keeps memory/IO per task modest and avoids a single task hogging all cores,
  especially on laptops.
  - It’s adjustable: Use the value that fits your machine.
      - 8 cores: kofam_cpus=1–2 (default is 2)
      - 16–32 cores: kofam_cpus=2–4, or keep 1 and cap concurrency with a maxForks if needed
      - If you see IO contention (many tasks hitting the profiles dir), bump to 2–4

  Bottom line: I suggested 1 to get many tasks running concurrently on your Mac; if you prefer fewer, faster tasks, set
  kofam_cpus higher.
